# FinTech design-system pass

Build a calm, recognizable product identity from centralized tokens and shared primitives.

- Use coordinated midnight, navy, slate, interactive, and elevated surfaces to create depth without making the interface colorful.
- Reserve blue for primary/selected states, emerald for success/deposit, amber for pending/information, indigo for secondary/security context, and red for destructive/negative states.
- Distinguish hero, primary functional, secondary data, interactive, status, inline-information, and table/list surfaces while retaining one geometry system.
- Reuse semantic buttons, cards, inputs, amount inputs, selects, tabs, badges, statuses, modals/sheets, tables/lists, skeletons, alerts, and empty/error states.
- Keep controls at least 44px where touch is expected; mobile financial primary actions should normally be 52–56px.
- Use one outline icon family and centralized crypto/bank icon mappings with deterministic fallbacks.
- Apply IRANYekanX consistently and use type size/weight/spacing—not extra borders—to establish hierarchy.
